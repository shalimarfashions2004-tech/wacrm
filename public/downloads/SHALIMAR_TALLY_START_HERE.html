SHALIMAR FASHIONS · SHOP SETUP

First, check Tally on the shop computer.

This is a local company-identity check. It is not a customer import or a live CRM sync. No data is uploaded.

1. Open the right company

  1. On the Windows computer running TallyPrime, open the intended Shalimar company. Keep Tally open.
  2. Press F1 (Help). The current check shows TallyPrime 7.1 (Latest) and Gold. Note the exact company name separately from the Tally title bar or company-selection screen.
  3. The About screen shows Client/Server with ODBC | Port 9000. Keep that port private. Gold supports the shop’s multi-user setup, but the exact company still must be checked on this computer.

If the local HTTP service is off, let the shop technician review the setting. Keep the port private. Do not add router forwarding, open it to the internet, or turn off the firewall.

2. Run one local check

  1. Extract the access-kit ZIP. Keep this guide and SHALIMAR_TALLY_CHECK.ps1 together.
  2. Open the Windows Start menu, type Windows PowerShell, and open it normally. Administrator access is not required.
  3. Type powershell.exe -NoProfile -File followed by a space, drag SHALIMAR_TALLY_CHECK.ps1 into that window to insert its path, then press Enter.
  4. Enter only the exact company name and Tally release when asked. Do not enter a password, licence number, API token or PIN.
  5. If your port differs, the technician can append -Port 9001, substituting the port actually shown in Tally.

If Windows says running scripts is blocked, stop and ask the shop technician to use the company’s approved method. This kit does not change execution policy, install software, or bypass a warning.

Install and rollback safely

  1. Copy the access-kit folder to the shop computer and keep it outside the CRM repository. Run it only while TallyPrime has SHALIMAR FASHIONS selected.
  2. Before the first read, record the existing Tally company backup and confirm the local HTTP/ODBC service is on port 9000. Do not enable router forwarding, public access, branch synchronisation, Import, or Execute requests.
  3. To roll back, stop the local worker and remove its scheduled task or folder. Leave Tally settings unchanged and retain the short receipt for review. No customer export or credential is required for rollback.

The worker is read-only and localhost-only. A successful identity check does not prove a CRM sync or marketing permission.

3. Return the result

The result is a short block of text beginning with {. Review it, then give only that block to the owner. It contains the company name, a fingerprint, the release you entered and the check status.

  • company_read_verified: the selected company’s identity could be read locally. Customer sales are not yet synced.
  • blocked: use the printed instructions. Do not keep changing settings or share private credentials.

No raw XML, customer names, phones, invoices, licence details or computer paths are saved by the check. The fingerprint is a hash of the returned company identifier. The release is staff-reported, not automatically verified.

What happens next?

  1. Confirm the version, company and read-only access.
  2. Read a closed month’s sales and compare invoice count and totals with a separate Tally report.
  3. Set up the authenticated bridge from this PC to Shalimar CRM. It needs its own narrow access key entered privately.
  4. Review customer identities, duplicate phones, language and WhatsApp permission before making broadcast lists.
  5. Verify Meta template approval and one approved image test before approving a customer campaign.

Buying from the shop does not automatically give WhatsApp marketing permission.
